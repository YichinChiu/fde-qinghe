# Demo 方案

## 链路与选择理由

**选定链路：月内复购率趋势核对**。在导入后的青禾库上，用运营 Agent 回答“近 12 个月每月月内复购率是多少、是否在下降”，并拆出分子（月内复购会员数）和分母（月内购买会员数），回答结论限定在新 CRM 覆盖范围内。

- **服务哪项会员运营工作**：沈总立项的核心判断是“会员复购率连续四个季度下滑”（W01 立项邮件），本周又在群里要求例会看“能跑起来、跟会员复购有关的东西，别再给我看 PPT”（客户材料 03）。小林的回访名单就是按“多久没买”拉的（客户材料 04），复购和沉睡是她每周的工作对象。
- **为什么先验证这条**：
  1. 它直接检验沈总的关键假设，而且是后续一切“找哪些会员重点经营”的前提：如果下滑不成立，或者下滑来自口径或覆盖问题，后面的名单和建议都要换方向。
  2. 用到的数据本周已经清洗并对账通过（订单、会员，金额与条数逐项平衡），指标在 W03 已有业务确认的定义（`monthly_repeat_rate` 等），不需要新开发。
  3. 它不触达会员、不打标签、不改系统，在本期授权边界内（业务模型 3.2）。
- **没选的链路**：月末付费会员复购（端点口径仍是暂定、未书面确认）、沉睡会员名单（勿扰名单有 30 人不在查询库，且本期未授权会员筛选和触达）、按门店拆分复购（指标库不支持，且门店编码、小程序订单门店含义待核）。

## 数据可用性、最小验证与已有证据

**用到的数据**：清洗后的 `orders`（167,665 条有效导入订单）与 `members`（119,754 个账户），数据版本 `qinghe-w04-v1.1`，覆盖 2024-09-01 至 2026-09-01（不含结束日）；指标 `monthly_repeat_rate`、`monthly_buyer_count`、`monthly_repeat_buyer_count`（有效订单＝已支付且实付大于退款，取消和全额退款不计）。

**覆盖与异常**（详见 `data_diagnosis.md`）：

- 不含门店老收银系统的部分会员消费（老周 MSG-05387、MSG-05395），范围未知；
- 168 条已注销会员订单、84 条超额退款订单已隔离，不计入；
- 订单状态映射是待核的建模选择（已支付与已完成关系未确认）；
- 月内复购指标只支持完整自然月、全门店全渠道。

**能否追溯**：每次运行保存 `result.json`（问题、回答、SQL、结果行）、`query_result.json` 和 `dataset_snapshot.json`（数据版本、哈希和覆盖说明）。数值已与独立查询逐月核对一致（2025-09 为 16.73%，2026-08 为 11.80%）。

**最小验证链路**：一个问题、三个指标、一个导入库：新 CRM 订单 → 清洗对账 → 导入库 → 月度复购指标 → Agent 回答（限定覆盖范围）→ 拆分子分母。

**已有证据**：

| 证据 | 结论 | 性质 |
| --- | --- | --- |
| run-02 | 在新 CRM 覆盖范围内，月内复购率从 2025-09 的 16.73% 波动降到 2026-07 的 11.37%，2026-08 为 11.80% | 数据结论 |
| run-04 | 同期月内购买会员数从 3,653 增到 5,473 个账户，月内复购会员数稳定在 581～699 个账户 | 数据结论 |
| 推断 | 复购率下降主要来自购买会员（分母）增加，而复购会员人数基本持平；新增的购买会员多为当月只买一次 | 推断，未验证新增会员的来源 |
| 补充查询（非 Agent 运行） | 月末付费会员复购率 2025-09～2026-08 在 20%～25% 之间，没有同样的下滑 | 数据结论，付费口径为暂定 |

## 暂不覆盖范围与待验证条件

| 暂不覆盖 | 原因 | 满足什么条件才扩大 |
| --- | --- | --- |
| 全公司、全部会员的真实复购 | 老收银系统部分消费未导出 | 老周给出老系统涉及的门店和时间段，或补导这部分消费 |
| 按门店或渠道拆分复购 | 指标库不支持（run-03）；门店编码、小程序订单门店含义待核；线上和门店不能混着比（小林 MSG-05418） | 新增分渠道的复购指标并由小林确认口径；老周提供门店主档 |
| 复购下降的原因 | 需要知道新增购买会员是谁（新注册、批量建档激活、还是老会员回流） | 增加按注册时间分组的复购指标，并与小林确认分组口径 |
| 沉睡会员名单、召回建议 | 本期未授权会员筛选和触达（王经理、小林）；查询库缺工作账勿扰名单中的 30 人 | 后续阶段书面确认筛选范围；名单必须并入工作账勿扰名单 |
| 付费会员复购 | 月末端点口径未书面确认 | 运营书面确认端点规则 |
| 2024-09 之前、终身首购 | 订单只覆盖 2024-09 起 | 补导更早订单 |

**调优记录**（`artifacts/w04/demo_annotation.json`、`demo_run.json`）：

- 问题定位：查询意图、SQL 和数值都正确；覆盖说明已在 `data_context` 中，指标约束也要求限定范围。毛病出在回答生成：原提示词只要求“解释统计范围、口径及限制”，没有要求把范围写进结论句。
- 修改：只在回答提示词增加一条“覆盖范围限定”规则（`customer/w04/answer_prompt.txt` 第 3 行，与 `product/w03_answer_prompt.txt` 的差异仅此一行）。

**仍未解决、下一步处理**：

1. 单问趋势时，Agent 只查了复购率本身，没有主动给出分子分母，用户看不到“分母翻倍、复购人数持平”这一关键事实，要靠追问（run-04）。下一步在 Harness 策略或工具层让比率类问题默认带出分子分母；属于另一处修改，按一次只改一处的原则留到下一轮，并对同一问题前后各跑一次。
2. 按门店、渠道拆分复购不支持（run-03）：先与小林确认分渠道口径，再在指标库新增指标。

## 判断说明：关键假设及继续、缩小范围、调整方向的条件

**关键假设**

1. 沈总所说的“复购下滑”可以用 W03 已确认的月内复购率来检验。
2. 新 CRM 的订单足以代表会员购买行为的主体部分，未导出的老收银系统消费不改变趋势方向。
3. 复购率下降反映会员真的复购变少，而不是分母结构变化或口径问题。

**最小验证链路与选择依据**：只用一个指标族（月内购买、复购人数与复购率）和一份已对账的导入库，先回答“下降是否存在、下降来自分子还是分母”。依据：这是沈总最关心的问题，数据和指标都已就绪，不触碰授权边界。

**已有证据与待验证条件**

- 假设 1：已有证据，指标定义来自 W03 业务确认材料，数值可复算。
- 假设 2：**未验证**。老周确认老收银系统有消费未导出，但范围不明；小林回访中有会员自述在门店用老卡购买。待老周给出范围。
- 假设 3：**部分被数据否定**。复购会员人数基本持平，下降主要来自购买会员数增加；新增购买会员是谁尚未验证。付费会员复购率没有同样下滑。

**继续、缩小范围、调整方向的条件**

| 决定 | 具体条件 |
| --- | --- |
| **继续**（把这条链路作为例会 demo，并下一步做“新增购买会员是谁”的拆分） | 老周确认老收银系统未导出的消费只涉及少数门店或较早时间段（例如不覆盖 2025-09 以后的多数门店），使近 12 个月新 CRM 订单能代表主体；且小林认可按月内复购率看复购 |
| **缩小范围** | 老周确认老收银系统覆盖大量门店的近期消费：demo 只讲线上渠道（小程序、商城）的复购，在线上复购指标补齐、小林确认口径之后再展示；门店部分明确写“数据不覆盖” |
| **调整方向** | 拆分后确认复购率下降完全由新增的一次性购买会员（如批量建档账户激活、新注册）带来，老会员复购人数稳定：把议题从“复购下滑”改为“新会员首购后的二次购买转化”，与沈总、小林重新确认要解决的问题；或者小林、沈总确认他们说的“复购率”不是月内复购率，则按其口径重新定义指标后再验证 |
