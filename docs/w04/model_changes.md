## 证据依据、来源与关联指标的一致性

- **数据证据**：各项的条数、日期范围见 `docs/w04/data_diagnosis.md` 第二节对应行，以及 `artifacts/w04/profile_report.json` 中的 `sample_rows`；不在此重复。
- **访谈依据**：只把访谈原话支持的内容写成客户规则；角色说“不能确认”“先不展开”的写成待核；我方选择单列在第 5 节“建模选择”并标明。
- **模型与指标的核对方法**：
  1. 对每项修订，查 `artifacts/w04/library/metrics.yml`、`member_monthly_summary.sql`、`ranked_orders.sql` 中是否有对应的筛选或计算。卡种清单 `('悦享年卡','家庭季卡')`、端点比较 `valid_until > month_end`、`ended_at > month_end`、有效订单 `status='paid' AND paid_cents > refund_cents` 都与修订后的模型一致，所以没有改 SQL 和语义定义。
  2. 模型新增的边界（卡种旧名、员工卡、状态映射、来源边界、注册日期口径）在指标层体现为 `catalog.json` 的约束说明，逐项见 `docs/w04/metric_changes.md` 的 C1～C5。
  3. 修订后的库在导入青禾数据的新项目上运行 38 项全部成功（`artifacts/w04/metrics_run.json`，2026-08 月），`validation.json` 通过；修订前后数值一致，证明修订只改说明、不改口径。
- **一致性结论**：模型中付费会员资格（卡种＋有效状态、按账户去重、端点暂定口径）与 `monthly_paid_*` 的 SQL 一致；有效购买（实付大于退款、取消不计）与订单类指标一致；注册日期（`join_dt`）与 `new_member_count` 一致。
